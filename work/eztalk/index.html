01

The problem

Recognition is one step.
Expression is the goal.

A person may still need to repeat an utterance, repair a transcription, or assemble a complete response. These steps add effort when speaking or operating a phone is difficult.

ezTalk is designed to reduce that effort through different levels of assistance. The user stays involved in choosing what to say. The effect on everyday communication still needs longer-term evaluation.

03

Engineering decisions

Constraints, choices & tradeoffs

Three choices that
shape the experience.

A

Offer assistance without taking over the message.

A fluent sentence may not reflect the intended meaning. The interaction offers candidate expressions that users can select or edit, while retaining a less assisted recognition path.

Tradeoff

A deliberate review step adds an action, but gives the user a way to reject generated wording. Semantic fidelity remains an evaluation priority.

B

Split speech processing and semantic assistance.

On-device target speaker extraction, voice activity detection, and recognition are used where the mode needs them. Cloud-based Gemini supports expression completion and reply suggestions.

Tradeoff

Local inference uses mobile resources; cloud assistance depends on connectivity and the text or context sent for processing. Not every mode works fully offline.

C

Make conversation roles explicit.

Reply distinguishes listening to a partner from expressing the user's own message. An explicit role switch provides a visible listening state before adding automatic speaker diarization.

Tradeoff

Manual switching adds an action. It keeps the role controllable and reuses the recording interaction without another automatic classification step. Usability needs further evaluation.

04

Privacy & security

Personal expression.
Thoughtful data boundaries.

Communication can reveal personal needs, relationships, and daily routines. Privacy is a design priority in ezTalk, shaping where speech is processed, what context is used, and how supported data is synchronized.

Local speech processing
On-device TSE, VAD, and ASR allow the selected speech-processing stages to run locally without requiring cloud audio processing for those stages.
Cloud boundaries
Cloud-assisted features send text and selected context to Gemini. Context components can be composed for the task, rather than including every piece of personal background. These features still involve external processing.
Encrypted sync
Supported sync flows encrypt data on the client before storage in Firestore. A passkey-protected recovery flow supports restoring access after reinstalling or changing devices, while avoiding a passkey prompt on every app launch.

Protection has a defined scope: encrypted sync does not cover every local file or cloud AI request. Recovery after losing all available passkeys remains unresolved, and the security design still needs formal review.

Current limits & evaluation

  • Target-speaker extraction can still admit loud, continuous background speech.
  • Cloud-assisted expression depends on network availability, and generated wording can misinterpret intent.
  • The modes run on real Android hardware, as reported during development. Communication benefit, accessibility outcomes, and performance improvements require further evaluation.
